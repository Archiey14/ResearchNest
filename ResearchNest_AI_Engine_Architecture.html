1. Executive Summary & Problem Formulation

Contemporary academic and industrial researchers are confronted with exponential growth in scholarly literature: over 2.5 million peer-reviewed scientific papers are published annually across global archives (arXiv, PubMed, IEEE, Nature, ACM). Traditional keyword search engines rely on brittle lexical string matching, creating high cognitive search friction and overlooking cross-disciplinary breakthrough papers that use differing terminologies for equivalent concepts.

ResearchNest resolves this problem by implementing a dual-engine architecture:

  • Verified Internal Catalog (Spring Boot + MySQL): Curated, landmark publications with peer-reviewed citation benchmarks, reading milestones, and verified takeaways.
  • Global Live Scholarly Stream (OpenAlex API): Real-time indexing of 250M+ international publications, enabling semantic querying across global preprints and peer-reviewed works.
  • Dedicated AI Recommendation Microservice (Python FastAPI + Scikit-Learn): High-dimensional TF-IDF vector space modeling, dynamic user centroid profile computation, and explainable cosine similarity ranking.

3. Mathematical Formulation of the AI Recommendation Engine

The AI Recommendation Engine (ai-service/engine.py) operates on Content-Based Filtering principles using vector space representations of textual scholarly works.

3.1 Feature Extraction & Weighted Document Composition

To capture domain significance without semantic drift, each paper p is transformed into a weighted synthetic corpus document D_p. Higher structural weights are assigned to salient metadata features:

Synthetic Document Weighting Equation
D_p = [Title] × 3 || [TopicTag] × 2 || [Field] × 2 || [Abstract] || [Authors]

Titles and topic keywords receive 3x and 2x repetition weight to prioritize domain specificity over general abstract terminology.

3.2 Term Frequency - Inverse Document Frequency (TF-IDF)

The corpus of N papers is transformed into a high-dimensional vector space using Scikit-Learn's TfidfVectorizer. The weight of term t in document d is calculated using sublinear term-frequency scaling:

Sublinear TF-IDF Transformation
TF(t, d) = 1 + ln(f_{t,d})   for f_{t,d} > 0

IDF(t, D) = ln((1 + N) / (1 + |{d ∈ D : t ∈ d}|)) + 1

v_d = w_d / ||w_d||_2   where w_{t,d} = TF(t, d) × IDF(t, D)

L2 Euclidean normalization guarantees that document length differences do not distort similarity metrics.

3.3 User Profile Centroid Vector Calculation

When a researcher saves or bookmarks a set of papers S = {p_1, p_2, ..., p_k} with corresponding normalized TF-IDF vectors {v_1, v_2, ..., v_k}, the engine synthesizes an aggregate User Profile Centroid Vector:

Researcher Centroid Vector
u_profile = (1 / |S|) × ∑_{s ∈ S} v_s

This centroid represents the user's active, multi-disciplinary research locus within the high-dimensional scientific manifold.

3.4 Cosine Similarity & Feed Ranking

To rank all candidate catalog papers against the user's profile, the engine evaluates the cosine similarity:

Cosine Similarity Measure
Similarity(u_profile, v_c) = cos(θ) = (u_profile • v_c) / (||u_profile||_2 × ||v_c||_2)

Scores are normalized to a human-readable match index between 75% and 98%:

MatchPercentage(c) = clamp(75, 98, round(86 + 12 × (Sim(c) / max(Sim)) - 2 × Rank))

3.5 Explainability & Nearest Anchor Attribution Engine

A critical limitation of traditional AI recommenders is the "black box" phenomenon. ResearchNest incorporates a deterministic Nearest Anchor Attribution Engine:

Anchor Paper Attribution
Anchor(c) = argmax_{s ∈ S} (v_c • v_s)

The engine identifies the specific saved paper that contributed the highest pairwise similarity, producing contextual explanations such as: "Recommended based on your saved paper 'Attention Is All You Need' (Artificial Intelligence)".

5. REST API Specifications

Service Method Endpoint Description
Spring Boot GET /api/papers Retrieve all catalog papers with optional search and field filtering.
Spring Boot GET /api/papers/{id} Fetch complete paper metadata, abstract, citations, takeaways, and BibTeX.
Spring Boot GET /api/papers/stats Aggregate real-time metrics (total papers, citations, field distributions).
Spring Boot POST /api/papers Persist new paper to MySQL and trigger automatic AI catalog re-index.
Spring Boot GET /api/recommendations/for-you Gateway proxy to fetch user recommendations based on saved IDs.
Spring Boot GET /api/recommendations/similar/{id} Gateway proxy to fetch similar papers for a given target publication.
Spring Boot POST /api/auth/register Register new user with name, email, password, institution, and department.
Spring Boot POST /api/auth/login Authenticate user credentials and issue session token.
Python AI POST /recommend/user Calculates profile centroid from savedPaperIds and returns ranked papers.
Python AI POST /recommend/similar Calculates pairwise similarity matrix and returns top-K related papers.
Python AI POST /sync-catalog Reloads MySQL catalog from Spring Boot and re-fits TF-IDF vectorizer.
